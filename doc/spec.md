## 1. ゲーム概要

### 1.1 コンセプト
Roblox標準アバターを使い、巨大なナンプレ盤面を複数人で協力してクリアするゲーム。  
プレイヤーは数字ブロックを拾い、盤面に配置していく。完成時にスコア上位者を表彰する。

### 1.2 ターゲット
- Robloxユーザー全般（ナンプレの知識がある程度あること前提）
- フレンドとわいわいチャット・通話しながらプレイしたいユーザー

### 1.3 基本スペック

| 項目 | 内容 |
|------|------|
| 想定プレイ人数 | 8〜16人（CPU追加可） |
| 1ゲーム目安時間 | 5〜10分 |
| 視点 | 3人称（Roblox標準）＋俯瞰カメラ切替 |

---

## 2. 難易度設定

ホストがゲーム開始前に選択する。3種類。

### 2.1 Easy
- 盤面サイズ: **9×9**
- 空きマス数: 少なめ（一般的な初級〜中級レベル相当）
- ヒント演出: 置けるマスのハイライト表示あり（検討中）

### 2.2 Normal
- 盤面サイズ: **9×9**
- 空きマス数: 中程度（一般的な中級レベル相当）
- ヒント演出: なし

### 2.3 Hard
- 盤面サイズ: **2つの9×9が重なる変形盤面（約12×15セル）**
- 構造: 3×3ブロックが14個、うち4個が中央で重複（片方の9×9の右下4ブロック＝もう片方の左上4ブロック）
- 重複ゾーンのセルは両方の9×9のルールを同時に満たす必要がある
- 空きマスが大幅に増えるため、16人参加時も十分な量が確保される

## 3. ステージ・マップ設計

### 3.1 レイアウト

```
┌─────────────────────────────┐
│           柵                 │
│  ┌──[数字ブロック列]──┐     │
│  │                    │     │
│[数]                  [数]   │
│  │   ┌──────────┐    │     │
│[字]  │          │   [字]   │
│  │   │ ナンプレ  │    │     │
│[ブ]  │  盤面    │   [ブ]   │
│  │   │ (床面)   │    │     │
│[ロ]  │          │   [ロ]   │
│  │   └──────────┘    │     │
│  │                    │     │
│  └──[数字ブロック列]──┘     │
│                              │
└─────────────────────────────┘
```

- 移動可能範囲は柵で囲まれた四角形エリア
- ナンプレ盤面はエリア中央の**床面**に展開
- プレイヤーは盤面の上を歩くことができる（1マス≒キャラ1〜2人分のサイズ）

### 3.2 ワールド座標系とスポーン位置

現在は **Map 1** アセットを使用。マップのバウンディングボックス中心から盤面中心座標を決定している。

| 要素 | 値 | 備考 |
|------|-----|------|
| 盤面中心 | `(-4307, 1862, 1923)` | Map 1 バウンディングボックス中心 X,Z・床面 Y |
| 列方向 | **X軸**（col 1〜9 → X = 中心X ± 40） | |
| 行方向 | **Z軸**（row 1〜9 → Z = 中心Z ± 40） | |
| セル原点計算式 | `X = -4307 + (col-5)*10, Z = 1923 - (row-5)*10` | Y = 1862.25（床面+セル厚み）。row1がスポーン側（手前） |
| ブロックスポーンY | `1863.0` | 床面 Y≈1862 + ブロック半高さ |
| スポーン地点 | Position `(-4286, 1862, 1760)` | Map 1 内蔵のSpawnLocation |
| 俯瞰カメラターゲット | `(-4307, 1862, 1923)` | 盤面中心と同値 |

**マップ変更時の修正箇所：**
- `GameManager.server.lua` の `BOARD_Y` / `BOARD_CENTER_X` / `BOARD_CENTER_Z`
- `BlockManager.server.lua` の `BLOCK_Y` / `BOARD_CENTER_X` / `BOARD_CENTER_Z`
- `CameraController.client.lua` の `OVERHEAD_TARGET`
- Studio 上の SpawnLocation の Position

### 3.3 数字ブロックエリア
- 配置場所: 盤面外周 四辺（`±65 studs` 付近）にランダム配置
- 数字: 1〜9
- 数量: 盤面の空きマスを埋めるのに必要な数 ＋ 各数字1個の余裕分（`BLOCK_EXTRA=1`）
- ブロック消滅: 落とされた・捨てられたブロックは**15秒後**に消えて初期位置にリスポーン（消滅直前に1.5秒かけてフェードアウト）
- ブロックサイズ: 2.5×1.2×2.5 studs。数字ごとに固有カラー（1〜9それぞれ色が異なる）
- 盤面サイズ: 1マス=10 studs、盤面全体=90×90 studs

### 3.4 数字カラー定義

数字 1〜9 にはそれぞれ固有のカラーが割り当てられており、以下の全 UI で統一使用する。

- ブロック本体の色
- 頭上数字バッジ（BillboardGui）の背景色
- 拾うプロンプト UI（カスタム BillboardGui）の背景色

| 数字 | 色名 | RGB |
|------|------|-----|
| 1 | 赤 | `(230, 80, 80)` |
| 2 | オレンジ | `(230, 150, 60)` |
| 3 | 黄 | `(220, 210, 60)` |
| 4 | 緑 | `(80, 190, 90)` |
| 5 | 水色 | `(60, 160, 220)` |

| 8 | シアン | `(90, 190, 190)` |
| 9 | 茶 | `(160, 120, 80)` |

## 4. ブロック操作仕様

### 4.1 拾う
- 数字ブロックに**一定距離（10 studs）まで近づく**と拾うプロンプトUIが表示される
  - PC: `[E] 拾う` と表示（カスタム BillboardGui）
  - モバイル: `拾う` と表示（カスタム BillboardGui）
  - UIはブロック上方 2.5 studs に表示し、**数字カラーの背景**＋数字＋操作テキストで構成
- 操作方法は 2 通り:
  - ProximityPrompt（近づいたときのキー/タッチ操作）
  - **画面右下の「拾う」ボタン**（後述 4.2 と共通ボタン）
- 同時に持てる数: **1個まで**
- 持っているブロックの確認:
  - キャラクターの手にブロックモデルが表示される（Roblox Tool）
  - **頭上に数字バッジ**（BillboardGui）が表示される（後述 4.4）
- ペナルティ中は拾えない

### 4.2 置く（本置き）
- 盤面の目的のマスに近づき（7 studs以内）、**置く/拾うボタン押下**で配置
  - PC: `[E]` キー または 画面右下の「置く」ボタン
  - モバイル: 画面右下の「置く」ボタン
- **「置く」ボタンは「拾う」ボタンと共用**（4.1・4.2 で同一ボタン）
  - ブロック未保持時: ボタン表示 →「拾う」、押下で最近ブロックを拾う
  - ブロック保持時: ボタン表示 →「置く」、押下で最近のマスに本置き
- 本置きのクールダウン: **3秒に1回**
- スパム制限: **30秒以内に不正解本置きを3回**行うとブロックを強制ドロップ。ドロップ後**15秒間**は新しいブロックを拾えない

### 4.3 捨てる（任意ドロップ）
- 持っているブロックをその場（プレイヤー前方）に落とす
  - PC: `[Q]` キー または 画面右下の「捨てる」ボタン
  - モバイル: 画面右下の「捨てる」ボタン
- 捨てたブロックは15秒後に初期位置にリスポーン

### 4.4 頭上数字バッジ

ブロックを持っている間、キャラクターの頭上に現在保持中の数字をバッジ表示する。

| 項目 | 仕様 |
|------|------|
| 表示形式 | 数字カラーの円形背景 ＋ 白文字数字（BillboardGui） |
| 表示位置 | 頭上 2.8 studs（常時カメラ方向を向く） |
| バッジサイズ | 64×64 px |
| 数字カラー | 1〜9 それぞれ固有色（セクション 3.4 参照） |
| 消滅タイミング | ドロップ・捨てる・ペナルティ・リスポーン時 |
| 他プレイヤーへの表示 | あり（AlwaysOnTop=false） |

### 4.5 正解・不正解の処理

| 状態 | 挙動 |
|------|------|
| 正解 | マスが**即ロック**（上書き不可）。スコア加算。 |
| 不正解 | マスに配置されるが、上書き可能。スコアは加算されない。 |
| 上書き | 後から置いたブロックで上書き可能（不正解マスのみ）。上書きされた元ブロックは**即リスポーン** |

## 5. カメラ仕様

### 5.1 通常カメラ（3人称）
- Roblox標準のキャラクター後方カメラ
- 移動可能

### 5.2 俯瞰カメラ
- `[V]` キー または **画面左下の「俯瞰/通常視点」ボタン**で切替
- 切替アニメーション: 0.4秒 Tween（Quad EaseOut）
- カメラ位置: 盤面中心の真上 高度 90 studs
- カメラ向き: 真下を向き、**画面上方向 = 盤面の -Z 方向（row 1 側）**
  - `CFrame.lookAt(pos, (0,0,0), upVector=(0,0,-1))` で実装
- 数字表示: SurfaceGui（Face=Top）の描画軸とカメラ上方向のズレを `TextLabel.Rotation = -90` で補正
- 俯瞰カメラの上方向: `upVector = (0, 0, 1)`（スポーン側 = -Z方向が画面下になるよう設定）
- 俯瞰中は**移動不可**（WalkSpeed=0、JumpPower=0）
- ブロックを持った状態でも切替可能
- 俯瞰モード中、**マーカー**の設置・確認が可能（盤面へのレイキャストで対象セルを特定）

## 6. マーカー機能（仮置き代替）

プレイヤー間のコミュニケーション・作戦共有ツール。ブロックを実際に置く操作とは独立している。

### 6.1 概要

| 項目 | 仕様 |
|------|------|
| 設置方法 | 俯瞰モード中のみ操作可能 |
| 見た目 | **プレイヤーカラー ＋ ▲数字**（例: 🔴▲5） |
| 意味 | 「自分がこのマスにこの数字を置く予定」の意思表示 |
| 上限 | 1人あたり**10個まで**（超えると古いものから自動消滅） |
| 他人のマーカー上書き | **不可** |
| 有効時間 | **無制限** |
| 自動消滅条件 | 該当マスに本置きが行われた時 |

### 6.2 目的
- 誰がどこを担当するかを視覚的に共有
- わいわいプレイ（チャット・通話）時の作戦立案を補助
- 俯瞰モードで盤面全体を見ながら複数のマーカーを配置できる

## 7. スコア設計

### 7.1 基本スコア
- 正解マスに本置きした瞬間に加算
- 不正解の本置きにはスコアなし

### 7.2 コンボボーナス
- 正解を連続して本置きするたびに倍率アップ
- 不正解・ブロックドロップでコンボリセット
- 倍率に上限あり（×3.0）

| 連続正解数 | 倍率 |
|-----------|------|
| 1回 | ×1.0 |
| 2連続 | ×1.5 |
| 3連続 | ×2.0 |
| 4連続 | ×2.5 |
| 5連続以上 | ×3.0（上限） |

※倍率の数値はプレイテストで調整予定

### 7.3 スピードボーナス（クリア時加算）
- 正確にプレイした人が有利になる設計
- 計算式: **基準値 × （正解数 ÷ 本置き総数）**
- 例: 基準値100、正解8回・総本置き10回 → 100 × 0.8 = **80点**
- 例: 基準値100、正解8回・総本置き8回（無駄打ちゼロ）→ 100 × 1.0 = **100点**
- 現在の基準値: **100点**（`SPEED_BONUS_BASE=100`）

※基準値・倍率はプレイテストで調整予定

### 7.4 完成貢献ボーナス（クリア時加算）
- クリア時、正解配置数が多い人ほど高ボーナスを獲得
- 同じゲームに多く貢献したプレイヤーが報われる設計
- 同率は同じ順位を付与

| 貢献度（正解配置数） | ボーナス |
|-------------------|---------|
| 1位 | +200点 |
| 2位 | +150点 |
| 3位 | +100点 |
| それ以下 | +50点 |

※ボーナス値はプレイテストで調整予定

### 7.5 完成ボーナス
- ナンプレ完成時、参加していた全プレイヤーに一律 **+50点** 加算（`COMPLETION_BONUS=50`）
- 協力してクリアした達成感を演出

### 7.6 スコア設計の意図
- 正確にプレイする人が勝つ
- 妨害行為（不正解を連打）はコンボリセット＋スパムペナルティ＋スピードボーナス低下で自滅する設計
- 完成ボーナス・完成貢献ボーナスにより協力プレイへの動機づけを担保

## 8. サーバー構成

### 8.1 基本方針

- **1サーバー = 1ゲーム**（全員が同じ盤面を協力してクリア）
- Place は1つ。ロビーエリアとゲームエリアを**同一マップ内**に共存させる
- マップ間テレポートは使用しない。ゲーム開始・終了時に **SpawnLocation への強制ワープ** で切替

### 8.2 エリア構成

| エリア | 場所 | 用途 |
|--------|------|------|
| ロビーエリア | ゲームフィールドとは別の場所 | ゲーム開始前の待機・設定 |
| ゲームエリア | 盤面・ブロックスポーンエリア | ゲームプレイ中のみ使用 |

- ロビー用 SpawnLocation とゲーム用 SpawnLocation を別々に配置
- ゲーム中にサーバーに参加したプレイヤーはロビーにスポーン

## 9. ゲームフロー

### 9.1 全体フロー

```
① 初回ロビー待機
   └─ プレイヤーがロビーエリアでスポーン・待機
       └─ ホストがスタートUI で設定
           ├─ 難易度（Easy / Normal / Hard）
           └─ スタートボタン押下

② ゲーム開始
   ├─ 全プレイヤーをゲーム用SpawnLocationに強制ワープ
   ├─ 盤面生成（GameManager）
   └─ ブロックスポーン（BlockManager）

③ ゲーム中
   ├─ 数字ブロックを拾って盤面に置く
   ├─ 途中参加者はゲーム用SpawnLocationに直接スポーンして即参加
   └─ 全マスが正解で埋まったらクリア

④ 結果発表
   ├─ 結果画面表示（クリア後 N 秒間）
   └─ バッジ付与（対象者）

⑤ 次ゲームへ（自動進行）
   ├─ ホストに「もう一度プレイしますか？」確認UI を表示
   ├─ ホストが「はい」→ ② に戻る（全員ワープ・盤面リセット）
   └─ ホストが「いいえ」→ 全員ロビーに戻す
```

### 9.2 ゲーム状態管理

サーバー全体で以下の状態を管理する：

| 状態 | 内容 |
|------|------|
| `Lobby` | ロビー待機中。ゲーム未開始 |
| `InGame` | ゲームプレイ中 |
| `Result` | 結果発表中・次ゲーム確認中 |

- ホストは**最初にサーバーに参加したプレイヤー**が自動的になる
- ホストが退出した場合は次のプレイヤーが引き継ぐ

### 9.3 途中参加
- ゲーム中（`InGame`）にサーバー参加した場合はゲーム用SpawnLocationに直接スポーンして**即参加**
- スコアは参加時点から加算開始
- 盤面は途中まで埋まった状態のままゲームに合流する
- 残りマスが少なくても気にしない（次のゲームで挽回できる設計）

### 9.4 CPUプレイヤー（未実装・将来対応）
- ホストが人数・強さを設定
- お助けキャラ兼ライバルとして機能

| 強さ | 動作 |
|------|------|
| 弱 | 数十秒に1回しか置かない。余ったマスを埋める程度 |
| 中 | 一定間隔でランダムに正解を置いていく |
| 強 | コンボを繋ぎながら積極的に置く |

## 12. UI仕様

### 12.1 レスポンシブ対応方針
- **絶対ピクセル値（fromOffset）は原則使用しない**
- 全レイアウト・サイズは `UDim2.fromScale()` による画面比率指定
- テキストサイズのみ `math.round(base * (ViewportX / 1280))` で比例スケール（最小0.55倍〜最大1.5倍にクランプ）
- モバイル判定: `UserInputService.TouchEnabled and not UserInputService.KeyboardEnabled`

### 12.2 HUD構成

| パネル | 位置 | 内容 |
|--------|------|------|
| スコアパネル | 左上 | 現在スコア（大）+ "SCORE"ラベル（小） |
| コンボパネル | スコア右隣 | コンボ倍率（×1.5〜×3.0 のとき表示） |
| 残りマスパネル | 右上 | "残り N マス" / 完成時 "完成！" |
| ゲイン ポップアップ | 左上（フロート） | +N 点をTweenでフロートアップ表示 |
| ペナルティパネル | 下中央 | "ブロックを落とした！ X.X秒" カウントダウン |
| カメラ切替ボタン | 左下 | 「俯瞰」/「通常視点」トグル。俯瞰中は青色ハイライト |
| 置くボタン | 右下 | ブロック保持中のみアクティブ |
| 捨てるボタン | 右下（置くボタン左） | ブロック保持中のみアクティブ |

> **補足**: Roblox 標準の Backpack（ホットバー）UI は `StarterGui:SetCoreGuiEnabled(Enum.CoreGuiType.Backpack, false)` で非表示にしている。Tool 装備時に画面下部に表示されるデフォルト UI（"NumberBlock" 文字列など）はこれにより抑制される。

### 12.3 アクションボタン

| 項目 | PC | モバイル |
|------|----|---------|
| ボタン幅 | 画面幅の13% | 画面幅の18% |
| ボタン高 | 画面高の7% | 画面高の9% |
| 置くボタン操作 | `[E]` キー / ボタン | ボタン |
| 捨てるボタン操作 | `[Q]` キー / ボタン | ボタン |
| 非アクティブ時 | 透明度0.55・操作不可 | 同左 |

#### ボタンアイコン

各ボタンには透過PNG画像アイコンを使用する。ボタン背景色（タイル色）の上に白抜きアイコンを重ねる構成。

| ボタン | アセットID | 表示条件 |
|--------|-----------|---------|

#### ボタンラベル（モバイルのみ）

モバイルでは各ボタン下部にアクション名を小テキストで表示し、**数秒後にフェードアウト**する。

| ボタン | ラベルテキスト | 復活タイミング |
|--------|-------------|-------------|
| 拾う/置く | 「拾う」/「置く」（保持状態に連動） | ブロックを拾うたびに「置く」が復活 |
| 捨てる | 「捨てる」 | ブロックを拾うたびに復活 |
| カメラ | 「カメラ」 | カメラボタン押下のたびに復活 |

- 初回表示: ゲーム開始から **3秒後** にフェードアウト開始
- フェードアウト時間: **1.5秒**（TweenService Quad EaseOut）
- フェードアウト中に復活トリガーが来た場合は途中でキャンセルして即復活
- PC では常時キー表示（`[ E ]` / `[ Q ]` / `[ V ]`）に切替・フェードなし
